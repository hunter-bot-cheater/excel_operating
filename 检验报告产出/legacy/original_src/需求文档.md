# 提取文件数据工具 —— 需求文档（v6）

> 本工具从「检验大报告」中按 BOM 的图号与数量，抽取若干件测量数据，生成独立小报告，并**就地推进基准报告文件的已用量后缀**。
> 前后端分离：`extract_core` 为纯逻辑层（无 GUI），`extract_core.api.run_batch` 为网页端集成点。

---

## 1. 背景与术语

- **BOM 文件**（兼容两种形态，表头在第一行）：
  - **PM-DM 型**：有「图号」列 + 「组件描述」列。
  - **WYS 型**：无图号列，「组件描述」列中嵌入图号（如 `远端轴套_93126082_Pla,PTFE-V0`）。
  - **数量列定位（唯一规则）**：表头第一行中**精确为「组件数量」**的列。
    - 只认这四个字，**不模糊匹配「数量」**（「组件计量单位数量」「基本数量」等一律不认），
      也**不做任何内容推断 / 降级适配**。
    - **找不到「组件数量」列 → 直接报 `BOM_READ_ERROR`**（错误信息列出该表实际表头），
      提示用户把数量列的表头改成「组件数量」。
  - **多表单只认第一张有效数据表（v6.1）**：BOM 含多个工作表时，**匹配、建任务、回写一律以
    第一张「表头有效 + 有「组件数量」列 + 有数据行」的表为准**，其余表不参与匹配、
    不建任务、不同步回写。
  - **表一图号唯一（v6.2）**：第一张有效数据表内同一图号视为唯一；匹配到**多于一行**
    同一图号（无论描述/数量是否相同，含完全相同的行）→ 直接报 `BOM_MULTI_MATCH`，
    不拆多行任务、不静默选一行（唯一放行口见 §3.0 描述收敛）。
  - 图号为空 / 数量为空的行**不参与**匹配。
  - **回写列（v4）**：表头形如 `第11套`/`第12套` 的列（识别规则 `^第\d+套$`）。回写时把 `日期/件数`
    写入「第N套」列 × 该图号行；BOM 中无该列则自动插入（位置见 §3.5）。
  - 「图纸 / 材质报告 / 尺寸报告」等视为**无关列**，插入新「第N套」列时须在其左侧。
- **报告文件（基准报告 / 大报告）**：文件名格式
  `图号_组件描述_总件数件_日期-已用(微信后缀).xlsx`
  例：`93019282-DM_翻转横撑_21件_26.4.09-12(1).xlsx`
  → **front**=`93019282-DM_翻转横撑`（`_N件_` 之前的整体），总件数=`21`，日期=`26.4.09`，已用=`12`。
  - **图号形态不限**：可含多个 `-`（`JH10-93021NDB-DM`）、可含 `_`（`93021WKD_prt`）、可含括号（`93010698-（1）`）、也可纯数字（`93126082`）。因此解析时**不拆分图号与描述**，front 整体参与匹配；新报告命名同样以 front 为前缀。
  - 微信 `(1)` 后缀忽略。
  - **后缀 `-已用` = 已经抽取过的件数（已用量）**。
  - **`-0` 表示已用完**（剩余=0），不可再选。
  - **文件名无 `-已用` 后缀** = 全新未用（已用量=0，剩余=总件数）。
- **任务**：报告文件池里 **front 能在 BOM 中匹配到**的那些文件，按其命中的 BOM 行拆成逐件任务（每行数量即 K）。front 未在 BOM 匹配到 → 该报告单独报 `NO_BOM_MATCH` 失败；BOM 中未被任何报告覆盖的行 → **静默跳过，不报错、不输出**。
- **剩余量** = 总件数 − 已用量。

## 2. 输入

- **1 个 BOM 文件**（拖入或按钮选择）。
- **报告文件池**：可拖入**单个文件夹 / 多个文件夹 / 多个文件**（任意组合）。文件夹递归收集其中的 `.xls/.xlsx/.xlsm`。所有收集到的文件按拖入顺序构成候选池。

## 3. 处理流程（报告池驱动）

> 方向：**以报告文件池为驱动**，而非 BOM。只有报告 front 能在 BOM 中匹配到的才会被处理；BOM 中其余行不报错、不输出。

1. 读取 BOM（列定位规则见 §1），得到 `(图号, 组件描述, 数量)` 行列表。
2. 解析候选池每个文件的文件名，得到 `(front, 总件数, 已用, 剩余)`：
   - 文件名解析失败 → 该文件单独报 `FILE_PARSE_ERROR`（不阻断其他）。
   - **front 未在 BOM 中匹配到** → 该文件单独报 `NO_BOM_MATCH` 失败（结果列表逐条 ❌，不影响其他文件）。
3. **仅对「报告覆盖到的 front」建立任务组**：命中的每条 BOM 行即一个任务，按 BOM 顺序逐行处理；BOM 中未被报告覆盖的行**直接跳过**。
4. 对每组，按下面「选文件规则」为每一行（任务）挑选来源文件并执行抽取。
5. 每完成一个任务，**立即**在界面显示该任务结果（成功/失败），并**实时**推进进度条。

### 3.0 front ↔ BOM 多信号匹配（v6，前级命中即止）

比较前先做归一化（canon）：去全部空白、全角→半角（括号/逗号/横线）、转小写。

报告携带三条身份信号（按可信度排序）：
- **dwg**：报告内部 DWG No（图号，从 B3 / 标签右侧读取，`.xlsx/.xlsm` 用 openpyxl 轻量读取，读不到回退纯文件名匹配）；
- **part**：报告内部零件名称（Part Description，F3 / 标签右侧读取）；
- **front**：文件名 `图号_描述` 整体（用户命名，可能缩写 / 带前后缀 / 加版本号）。

匹配原则：**联合信号优先于单一信号**（图号+描述同时对上，胜于只有图号对上）。

| 级 | 信号 | 规则 |
|---|---|---|
| S1 | 内部双键全等 | `canon(图号)==canon(dwg)` 且 `canon(描述)==canon(part)` → 唯一即赢（图纸真值互相印证） |
| S2 | 文件名双键联合 | ① 拼接全等：`canon(图号_描述)==canon(front)` → **L2**：front 按 `_` 分段，图号段与 BOM 图号文本/数字匹配 **且** 描述段命中该行描述（多对多用描述消歧） |
| S3 | 内部单键 | 内部图号全等 + 零件名收敛（互为子串）；**零件名对不上任何行时不采信图号**（防 `93019282-DM` 图号 + `翻转横撑` 误锁「弹簧压板」行）；无零件名且图号唯一命中则采信 |
| S4 | 文件名单键 | ② 图号前缀回退：`canon(front)` 以 `canon(图号)+"_"` 开头（不同图号前缀都命中取最长）；**同图号多行 → 描述精确收敛到唯一行，否则直接报错** → ③ 分段集合（WYS 型）→ ④ 数字键（见下） |

- **数字键（④）**：适配「报告文件名只写了图号的一部分 / 图号被加前后缀 / 图号藏在任意段」。
  - 键 = `digits_key`（字符串里全部数字拼起来），BOM 侧取「图号」；**front 的每一段**都取键与 BOM 比对
    （例 `91010070_E.1_20260814_Pd93010410_保护盖1` → 第四段 `Pd93010410` 的键 `93010410` 命中 BOM）。
  - 键位数 `< 5` 不参与（`GB/T 119.1` → `1191` 这类标准件目录号误撞概率高）。
  - 命中后依次收敛：① 保留「组件描述出现在 front 里」的行 → ② 保留「图号文本本身出现在 front 里」的行；
    仍多于 1 行 → 报 `BOM_MULTI_MATCH` 并列出候选，**绝不瞎选**。
- **描述精确优先于包含（v6.1）**：描述收敛一律「**全等 > 子串**」——若存在与 front 描述段
  **完全一致**的 BOM 描述行，只保留这些行；没有精确行才允许「描述是 front 子串 / front 描述是
  描述子串」的包含匹配。防「`X`」被「`X1`」这类子集描述行干扰、防「焊接管」被「CF100焊接管」干扰。
- **表一图号唯一，多行直接报错（v6.2，取代 v6.1「多行任务 vs 命名不严格」）**：
  用户确认第一张有效数据表内图号不重复。任何一级命中**多于一行**（含完全相同的行）
  → 一律报 `BOM_MULTI_MATCH` 并列出候选行，**绝不拆多任务、绝不静默选一行**；
  唯一放行口 = 描述**精确收敛到唯一一行**（如 `92011601_腔体拼焊板2-试样` → 只命中
  「腔体拼焊板2-试样」行；纯图号 `92011601` → 直接报错）。
- **歧义保护**：任何一级命中多个行（图号/描述/数量任一不同或完全相同）→ 报 `BOM_MULTI_MATCH`
  （含「歧义」字样），列出全部候选，绝不瞎选。
- **描述列识别（v6）**：优先认表头**「组件描述」**，其次认**「物料长描述」**（`91010070_E.1_20260814_Pd-测试版.XLSX` 型 BOM）；两者都找不到则 desc_col=None，描述校验自动降级为纯图号。

### 3.1 扣减基准文件算法（多来源拼接，v5）

**核心：一个任务（BOM 行，需 K 件）可由多份基准报告共同承担。**

- 候选 = 图号匹配 且 剩余 > 0 的文件（已用完 `-0` 的直接排除）。
- 对每个任务（数量 K）：
  1. 把所有候选按**剩余量升序**排序（相同剩余保持拖入顺序）——即优先消耗「最接近用完」的文件；
  2. 依次扣减：对每个文件取 `min(该文件剩余, 还需件数)`，**能用满就用满**（余量不足 K 就把该文件整份扣完），
     剩余差额继续用下一个文件补足，直到凑够 K 件；
  3. **目标**：尽可能把基准文件「用满」、让「有剩余（没用完）的文件数」尽可能少。
- **示例**：两份基准报告，一份剩 5 件、一份剩 10 件，某任务需 6 件
  → 先用满剩 5 件那份（该文件用尽，后缀推进到 `-0`），再从剩 10 件那份取 1 件（该文件推进到 `-1`）。
  （任务来源 = 这两份文件，各自贡献其**接续的件号**，合成一份 6 件新报告。）
- **不足**：若该图号**所有候选剩余合计 < K** → 该任务报错 `NO_REMAINING`
  （原因「图号 X 所有基准文件余量合计不足（需要 K 件；…）」）。
- 每个任务开始前都重新做上述判定；拖入的文件数量不限。
- **事务**：多来源任务中，任一来源改名失败 / 生成或保存失败 → **全部来源恢复原名、不生成新文件**。

### 3.2 单任务抽取（多来源，事务 / 原子）

对每个来源分片（各自当前已用量 `used`，本片抽 `count` 件；合计 = K）：

1. 校验（对每个分片）：`used + count ≤ 总件数`（否则 `K_EXCEEDS_REMAINING`）；该片第 `(used+1)~(used+count)` 件在报告记录中均存在（否则 `SAMPLE_NOT_FOUND`）。**K 无硬上限**（v5 起支持 K>5，见 3.2.1）。
2. **先推进各来源已用量（就地改名）**：每个分片文件后缀由 `-used` 改为 `-(used+count)`；若 `used+count == 总件数`（用完）则改为 `-0`。
   - 例：`-2` 用 2 件 → `-4`；`-10` 用 2 件（总 12）→ `-0`。
3. **再生成新报告**：以第 1 份来源的目标工作表为模板（Excel COM 整表复制，保留格式/合并单元格/形状），清空测量区，按分片顺序把各来源「接续的件」填入输出列；测量序号改为 `1~K`；总数/检查数改为 K；工作表名改为**日期**（K>5 时为 `日期-1`、`日期-2`…，见 3.2.1）。
   - 多来源时：序号 1..K 按「分片顺序」连续拼接（第 1 片的件在最左，其后是第 2 片…）。
4. **回滚保证**：仅在所有来源改名成功「且」新报告成功生成后才保留改名；任一步失败（改名/COM/保存），**恢复全部来源原名、不生成新文件**。即**单任务失败时：来源文件不变、新文件不生成**。

#### 3.2.1 K > 5：自动拆多张表（v5 新增）

单张输出表最多承载 `SHEET_MAX = 5` 列测量件。当 K > 5 时，输出报告含
`n_out = ceil(K / 5)` 张工作表，每张最多 5 列：

- 第 s 张表（s=0,1,…）承载本任务的第 `s*5+1 ~ min(s*5+5, K)` 件；
- **测量序号为本地连续序号 `1..K`**（不是全局件号）：第 s 张表从左到右为 `s*5+1 … s*5+5`；
- **每张表的「总数 / 检查数」都写 K**（总数=总件数，与用户口径一致）；
- **最后一张表**未用到的列：测量数据与序号**留空**；
- 表名：K≤5 时单表名 = 日期；K>5 时 = `日期-1`、`日期-2`…`日期-n`；
- 数据来源：每件的数据按其**全局件号**从来源报告（可能跨多张来源表）读取后，落到对应输出表的对应列。

> 例：K=12 → 3 张表（5+5+2）。前两张各 5 列，第三张用 1、2 列（序号 11、12），其第 3~5 列留空。

### 3.3 新报告命名

- `图号_组件描述_K件_日期.xlsx`（如 `93019282-DM_翻转横撑_2件_26.4.09.xlsx`），保存到输出目录。
- 同名冲突自动加 `(2)`、`(3)` …。

### 3.4 失败隔离

- 某个任务失败（余量不足 / 文件解析错 / COM 错 / 样本缺失等）→ 该任务单独报错，**其余任务继续**。
- 已成功提交的任务不再回滚（仅失败任务回滚）。

### 3.5 BOM 回写（v4 新增）

> 目的：每转换完一个报告文件，就把该件的「日期/件数」登记回 BOM 的「第N套」列。

- **触发条件**：GUI 的「当前第几套」**必填正整数 N**；留空/非法不允许开始。`run_batch(..., round_no=N)`。
- **写入位置**：BOM 中表头形如 `第N套` 的那一列 × 该任务匹配到的图号所在**行**（表一图号唯一，
  故每图号至多一行；匹配到多行 → 该文件在匹配阶段即报错，不进入回写）。
- **只写第一张有效数据表（v6.1）**：BOM 含多张工作表时**只写主表（第一张有效数据表）的精确行**，
  其余表不插入列、不写入（匹配、建任务、回写三处口径一致，均为第一张表）。
- **写入内容**：`日期/件数`，如 `2026.6.15/1`。
  - 日期 = **基准报告文件名里的日期**（`ParseResult.date`）；
  - 件数 = 本次抽取件数 K（= 该 BOM 行「组件数量」）。
  - 以文本写入（单元格 NumberFormat = `@`），避免被 Excel 误判为日期。
- **列不存在时自动插入**：新建一列，列名 `第N套`，位置 = **所有 `第X套` 列的最右边**（若一个 `第X套` 列都没有，则取「图纸 / 材质报告 / 尺寸报告」等无关列的最左边；再无则紧邻「组件数量」右）。
- **回写方式**：原地修改用户拖入的 BOM 母版（保留原格式），**不做备份**（用户要求：BOM 不需要 .bak，直接就地改）。
- **失败不阻断**：BOM 打开/插入列/写入/保存任一失败均归入 `bom_write_errors`，**不计入任务失败数**，界面以 ⚠️ 单列提示；抽取任务本身仍算成功。
- 无成功任务时不动 BOM。


## 4. 输出目录

- 默认：来源文件所在目录。
- 可由用户在「③ 输出目录」选择其他目录（新报告存此处；来源文件仍在原目录就地改名）。

## 5. 错误码一览

| 错误码 | 含义 | 处理 |
|---|---|---|
| `FILE_PARSE_ERROR` | 报告文件名无法识别 / 扩展名不支持 | 该文件单独报错 |
| `BOM_READ_ERROR` | BOM 读取失败 / 无有效行 / 找不到数量列（含内容推断也未找到） | 整体报错，终止 |
| `NO_BOM_MATCH` | 报告图号未在 BOM 中匹配到（或对应数量空） | 该报告单独失败 ❌（不影响其他文件） |
| `K_EXCEEDS_REMAINING` | used+K 超过总件数 | 该任务报错 |
| `NO_REMAINING` | 图号无余量足够的文件 | 该任务报错「没有足够余量」 |
| `SAMPLE_NOT_FOUND` | 报告未记录到对应件号 | 该任务报错，来源不改名 |
| `RENAME_ERROR` | 来源文件名更新失败（被占用） | 该任务报错 |
| `COM_ERROR` | Excel 打开/复制失败（被占用） | 该任务报错，回滚 |
| `SAVE_ERROR` | 保存新报告失败 | 该任务报错，回滚 |
| `BOM_WRITE_ERROR` | BOM 打开/插列/写入/保存失败 | ⚠️ 单列告警，**任务仍算成功** |

## 6. 模块划分（前后端分离）

```
extract_core/
  errors.py        ExtractError(code, reason, file)
  models.py        ParseResult / BomRow(含 row/sheet) / BomMeta / Candidate / SheetLayout / ReportInfo
  filename_parser.py  parse_report_filename
  bom_reader.py    read_bom_ex（行号+表头元数据；数量列须精确表头「组件数量」）/ read_bom / match_front /
                   match_report（多信号交叉验证）/ find_round_col / find_insert_col（「第N套」列定位与插入位）
  bom_writer.py    BomWriter（插入列 + 写「日期/件数」+ 只写第一张有效数据表 + 保存；不做备份）
  report_reader.py detect_layout（模板无关表头探测；.xls 经 COM 转临时 .xlsx 读取）/
                   extract_identity（轻量读取报告内部 DWG No + 零件名称，仅 openpyxl、不启 Excel）
  extractor.py     run_one_task_multi（多来源单任务拼接，事务回滚）+ run_one_task（单来源包装）+ COM 生成
  api.py           run_batch（BOM 分组 + 扣减基准文件算法 _plan_segments + BOM 回写 + 逐任务回调）/ process_report
```

- `run_batch(bom_path, report_paths, out_dir, round_no=None, on_progress, on_task)` 返回
  `{"ok_count", "fail_count", "tasks":[...], "file_errors":[...], "skipped_rows":[],
    "bom_write_errors":[...], "bom_backup"}`，
  每个 task 为 JSON 可序列化 dict；`on_task(dict)` 在每个任务完成时回调（GUI 实时展示用），`on_progress(pct, msg)` 更新总进度。
- 网页端：拿到 `tasks` 中 `ok=True` 的 `output` 作为下载；`ok=False` 的 `reason` 展示。

## 7. GUI

- 与「审核不合格数据」「检验报告格式转换」一致：卡片式、可拖拽、进度动画。

## 9. 已知假设 / 边界

- 图号匹配为**多信号交叉验证**（`match_report`）：S1 内部双键全等 → S2 文件名双键联合（① 拼接全等 + 图号段×描述段）
  → S3 内部单键（图号全等 + 零件名收敛）→ S4 文件名单键（② 图号前缀+描述校验 / ③ 分段集合 / ④ 数字键）。
  归一化见 `canon`（去空白、全角→半角、转小写）；`match_front` 保留为无内部信号的兼容入口。
- **v6 修复（旧②级误配）**：报告 `93019282-DM_翻转横撑` 此前会误配到 BOM 行「93019282-DM／弹簧压板×3」。
  现由 S1/S2 的联合信号先行命中「JH-YCL-93019282-DM（按图加工）／翻转横撑×1」；S3 在零件名对不上任何行时**不采信图号**。
  **②级已加描述校验**：同图号多行时用「描述精确出现在 front 里」收敛到唯一行；
  收敛不了 → 直接报 `BOM_MULTI_MATCH`（v6.2 起不再保留「多行任务」语义）。
- **v6 修复（物料长描述）**：描述列表头为「物料长描述」时同样识别为描述列（「组件描述」优先），②③④ 的描述校验不再缺数据。
- **「只按图号匹配」不安全（实测数据）**：桌面 `PM-DM第三套BOM.XLSX` 中，有数量的行里
  存在**多个图号对应多种组件描述**（如 `92011601`→腔体拼焊板1~6-试样、`93021561`→CF100/ISO200/CF40焊接管与水槽盖板A等、
  `93218103`→T0.2/T0.5-Hard stop、`93019282-DM`→弹簧压板/翻转横撑；另有 `GB`、`GB/T 119.1`、`GB/T 70.1-2008` 等标准件目录号）。
  **结论**：不能无脑只按图号选行，必须「数字键 + 描述校验 + 多义报错」。
- **数字键扫描全部段**：图号可能藏在文件名任意段（如 `91010070_E.1_20260814_Pd93010410_保护盖1` 中 `93010410` 在第四段），
  故对 front 每一段取数字键（≥5 位）与 BOM 图号比对。
- **多行任务 vs 歧义（v6.2 唯一行）**：第一张有效数据表内图号唯一——匹配到多行同一图号
  （含完全相同的行）一律直接报 `BOM_MULTI_MATCH`（列候选行），**不再区分**「多行任务/命名不严格」；
  仅描述精确收敛到唯一一行时放行。不再出现「②级返回多行任务、④级报歧义」的不一致。
- 报告模板无关（表头文字探测），单 part / 双 part 均支持；内部身份读取失败自动回退纯文件名匹配。
- 来源文件改名是**原地覆盖**（非另存副本），用户已确认。
- K 无硬上限；单张输出表最多 5 列（`SHEET_MAX=5`），K>5 自动拆多张表（见 3.2.1）。
- 一个任务**可由多份基准报告拼接**（见 3.1）；输出报告的日期/命名取第 1 份来源。
- BOM 必须含**表头为「组件数量」**的数量列，否则报 `BOM_READ_ERROR`（**无降级适配**，见 §1）。
- BOM 可能包含**多张数据表**：匹配/建任务/回写**一律只认第一张有效数据表**（其余表不参与）；
  第一张表内图号唯一，匹配到多行同图号 → 直接报 `BOM_MULTI_MATCH`。
